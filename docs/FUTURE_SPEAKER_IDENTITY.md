# 说话人身份与声纹识别

状态：2026-09-15 经宁确认提前实现；功能闭环已落地，待真实录音校准。

跟踪任务：<https://github.com/MN0709/meeting-review/issues/1>

## 为什么仍要分阶段验收

声纹识别涉及多人重叠发言、录音设备差异、注册样本质量、误认责任和生物特征隐私。因此代码已实现并不等于准确率已达标：本轮先交付安全回退、授权、删除和人工纠错，再用真实录音校准阈值。

## 当前已实现

- WeSpeaker 本地说话人分离、特征提取和已知身份匹配。
- `speaker_profiles` 团队级身份库与 `meeting_speakers` 单场标签，两者分离。
- 用户首次确认、仅保存本场名称、授权后记住声音和声纹删除。
- 转写片段保存本场说话人标签；已识别姓名会进入 LLM 分析上下文。
- 低于阈值或与第二候选差值不足时回退待确认，不强制归责。

这些是数据流和接口位置的预留，不代表声纹算法已经实现。

## 计划中的数据扩展

```text
members
  id / team_id / name
      |
      | 1:N
      v
speaker_profiles
  id / member_id / embedding / model_version / consented_at / deleted_at

meeting_speakers
  id / meeting_id / local_label / member_id? / confidence / confirmed_by_user
      |
      | 1:N
      v
transcripts
  speaker_label + future meeting_speaker_id?
```

- `speaker_profiles` 只在成员明确授权后创建，按团队隔离，可单独删除。
- `meeting_speakers` 把单场会议的“说话人 1”与长期成员身份分开，允许无法识别和人工纠正。
- `confidence` 低于阈值时必须显示“待确认”，不能自动把决策归给真实成员。
- 历史 `transcripts.speaker_label` 保持兼容；未来新增外键而不是复用字符串充当永久身份。

## 分阶段实现

### 阶段 1：说话人分离＋人工改名

- 将片段区分为“说话人 1/2/3”。
- 用户在报告生成后把本场标签映射为成员。
- 映射后重新计算发言时长，并更新引用展示。

### 阶段 2：团队级名称记忆

- 保存经过用户确认的会议标签与成员映射。
- 下一场会议先给出推荐身份，仍由用户确认。
- 错误纠正必须反馈到映射记录。

### 阶段 3：可选声纹注册

- 成员主动录制或选择清晰片段建立声纹。
- 本地生成并保存声纹特征，不保存注册原始音频。
- 对设备变化、噪声和多人重叠做置信度校准。

### 阶段 4：跨会议个人责任追踪

- 在身份可靠且经用户确认后，才按成员聚合承诺、未完成事项和发言统计。
- 每项归责继续保留会议、原话和时间戳来源。

## 上线门槛

- 未知说话人可以安全回退，不强行匹配。
- 误认率、拒识率和人工纠正成本都有真实会议测试数据。
- 用户能查看、纠正和删除自己的身份映射与声纹资料。
- 页面明确说明生物特征处理目的、保存位置和删除方式。
- 自动归责必须经过置信度阈值与用户确认；不得仅凭 LLM 猜测姓名。

## 面试时的准确说法

> 我没有为了 Demo 强行上线声纹识别，而是把它拆成说话人分离、人工映射、团队级记忆和可选声纹注册四阶段。当前数据库已经有团队成员、可空说话人标签和转写后处理插入点，并在 GitHub 中维护独立的 Post-MVP 任务；这样后续扩展不会推翻会议与报告主模型，同时避免早期错误归责和生物特征隐私风险。
