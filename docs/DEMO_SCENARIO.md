# Demo 主场景：普通产品项目组周会

状态：宁已于 2026-09-13 确认。

## 场景定位

一个 5-6 人普通产品项目组围绕同一产品连续开周会。会议不是为了生成一份漂亮纪要，而是持续确认：

- 上周承诺的事情完成了吗？
- 本周形成了哪些明确决策？
- 每个行动项由谁负责、何时完成？
- 哪些问题还没有结论？
- 几周以后能否查到某个决定是在什么时候、基于什么原话形成的？

## Demo 信息结构

```text
团队：产品项目组
└── 项目：产品上线 MVP
    └── 周期会议：产品周会
        ├── 第 1 周：确认目标用户与 MVP 范围
        ├── 第 2 周：检查原型与真实反馈
        └── 第 3 周：决定上线范围与责任分工
```

## Demo 必须展示的连续性

1. 第 1 周产生结构化决策、行动项和遗留问题。
2. 第 2 周会前自动看到第 1 周未完成行动项。
3. 第 2 周可以更新行动项状态，并形成新的决策。
4. 第 3 周能搜索“什么时候决定先做固定团队周会”，返回对应会议、原话和时间戳。
5. 任何历史搜索和回顾都不能出现其他团队的数据。

## 通过标准

- 用户不读完整转写，也能在 3 分钟内说清本周决定和责任人。
- 周期回顾不是重新生成泛泛摘要，而是引用上一场结构化结果。
- 搜索结果可以回到具体会议和转写片段。
- 负责人或期限没有明确证据时显示“未明确”，不能猜测。

## 面试叙事

> 我选择普通产品项目组周会作为主场景，因为它天然存在连续决策、跨周待办和责任追踪。Demo 使用三次连续周会验证产品不是一次性的 AI 纪要，而是会随着项目推进积累的团队决策记忆。
