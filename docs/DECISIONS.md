# 决策记录

## D-001：产品主线定版

- 日期：2026-09-13
- 状态：已确认
- 决策：采用 Granola 信息架构、Fellow 报告结构和飞书中文体验，执行 10 天路线。
- 影响：项目从单次团队报告升级为“项目文件夹＋连续会议记忆”。

## D-002：保留内容分类，但不做独立文件管理

- 日期：2026-09-13
- 状态：已确认
- 决策：用户选择项目，AI 推荐标题、项目和标签，用户确认后生效。
- 原因：分类是跨会议记忆的基础，不是主要卖点；完全自动分类一旦出错会降低信任。

## D-003：声纹识别不作为 10 天主线

- 日期：2026-09-13
- 状态：已确认
- 决策：首版支持人工校正说话人显示名；自动声纹作为独立 Post-MVP 项目，按“分离 → 人工映射 → 团队级记忆 → 可选声纹注册”分阶段实现。
- 原因：当前更需要验证决策追踪和跨会议记忆的用户价值。
- 扩展设计：`docs/FUTURE_SPEAKER_IDENTITY.md`。

## D-004：时间戳定位转写，不承诺历史音频回放

- 日期：2026-09-13
- 状态：已确认
- 决策：维持音频转写后删除的隐私策略；报告时间戳展开原始转写上下文。
- 影响：不能完全照搬飞书妙记的回听交互，界面必须真实说明能力边界。

## D-005：Codex 单一执行责任制

- 日期：2026-09-13
- 状态：已确认
- 决策：不再让 Kimi 单独产出并行方案；Codex 维护规格、实现、测试、中控台和日报。
- 例外：只有任务边界清晰且不会分裂产品上下文时，才使用内部并行执行。

## D-006：吸收 Read AI 的周期回顾与历史搜索

- 日期：2026-09-13
- 状态：已确认
- 决策：在项目下增加可选会议系列；周期会议回顾上次决策、未完成行动项和遗留问题；历史搜索限定团队/项目范围并返回来源。
- 技术：MVP 先用 SQLite 结构化字段和 FTS5，不直接上向量数据库。
- 原因：这与连续会议记忆的核心价值一致，同时能复用现有 SQLite 和结构化报告。

## D-007：开源复用必须经过许可证与架构审查

- 日期：2026-09-13
- 状态：已确认
- 决策：MIT/Apache-2.0 项目可在记录来源后选择性复用；AGPL 项目不复制代码；闭源竞品只借鉴公开产品模式。
- 核查清单：`docs/OPEN_SOURCE_REVIEW.md`。

## D-008：Demo 使用普通产品项目组周会

- 日期：2026-09-13
- 状态：宁已确认
- 决策：以普通产品项目组的连续周会作为统一演示和验收场景，不设定为创业团队，也不把人数固定为 5-6 人。
- 目的：同时验证项目归档、周期回顾、跨周待办、决策证据和历史搜索。
- 场景说明：`docs/DEMO_SCENARIO.md`。

## D-009：参会人数可变

- 日期：2026-09-14
- 状态：宁已确认
- 决策：产品和 Demo 不设置 5-6 人硬限制；同一项目不同会议的参会人数可以增加或减少。
- 边界：人数可变不等于准确率不受影响；更多人、重叠发言和收音质量仍需真实录音验证。

## D-010：项目成员稳定、会议参会者可变

- 日期：2026-09-14
- 状态：宁已确认
- 决策：一个项目有相对稳定的成员范围，但每场会议可以只有部分成员参加，也可以出现临时参会者。
- 数据影响：项目成员与单场参会者应分开建模，不能用一次会议名单覆盖项目成员关系。

## D-011：Demo 场景不等于产品定位

- 日期：2026-09-14
- 状态：宁已确认
- 决策：产品定位统一为“需要沉淀连续内部会议的团队”，不限定产品项目组；普通产品项目组周会仅用于 Demo 和测试数据。
- 影响：页面、README 和产品介绍使用中性定位，Demo 文档可以继续使用产品项目组案例。

## D-012：上传前选择人工文件夹

- 日期：2026-09-14
- 状态：宁已确认
- 决策：用户先创建或选择项目文件夹，再上传会议；标题可以不填。AI 转写后只能建议标题、标签和归档调整，不能自动移动会议。
- 兼容：历史数据和 API 上传仍可处于“未分类”，但新版页面的新上传要求选择文件夹。

## D-013：删除文件夹时由用户决定会议去向

- 日期：2026-09-14
- 状态：宁已确认
- 决策：删除文件夹前提供三种选择：保留会议并移入“未分类”、连同会议一起删除、取消操作。
- 数据边界：连同会议删除会级联删除会议元数据、转写稿和报告，不可恢复；处理中会议禁止连带删除。只删除文件夹时，处理中会议也可安全移入未分类。

## D-014：项目文件夹最多两级

- 日期：2026-09-14
- 状态：宁已确认
- 决策：支持“一级文件夹 → 二级文件夹”，不支持第三层；例如“客户项目 → 2026年度”。
- 安全边界：一级文件夹仍有二级文件夹时禁止删除，用户须先处理二级文件夹，避免意外级联。

## D-015：永久删除必须二次确认

- 日期：2026-09-14
- 状态：宁已确认
- 决策：用户在第一层选择“连同会议删除”后，再弹出永久删除确认。
- 必须明示：会议元数据、转写稿和报告都会删除，且不可恢复；只有第二次确认后才调用删除接口。

## D-016：历史会议允许人工移动

- 日期：2026-09-14
- 状态：宁已确认
- 决策：会议归档后允许用户手动移动到另一个文件夹；操作前必须展示目标文件夹并确认。
- 数据边界：只更新会议的 `project_id`，转写稿和报告完整保留；目标文件夹必须属于当前团队。
- AI 边界：AI 可以建议归档调整，但不能自动移动会议。

## D-017：会议历史使用左侧文件夹树

- 日期：2026-09-14
- 状态：宁已确认
- 决策：成熟版历史入口采用左侧两级文件夹树、右侧会议列表，不再使用顶部下拉筛选。
- 交互修正：移动会议时仍显示当前文件夹，但标记为“当前”并禁用；其他文件夹作为可选目标，避免用户误以为目录丢失。

## D-018：一级文件夹汇总二级会议

- 日期：2026-09-14
- 状态：宁已确认
- 决策：点击一级文件夹时，右侧显示直接归属于本级及全部二级文件夹的会议；点击二级文件夹时只显示该目录会议。
- 数字口径：一级文件夹旁的数量同步使用本级与二级之和，不能继续显示直接会议数。

## D-019：用户界面收敛为单层项目

- 日期：2026-09-14
- 状态：宁已确认；替代 D-014、D-017、D-018 的可见界面部分
- 决策：用户只看到一层“项目”，不再创建或展示二级项目；上传区只选择项目，新建、改名、删除统一放在左侧项目栏。
- 兼容策略：数据库继续保留 `parent_id` 扩展位；若已有二级历史数据，会议自动归并显示在所属一级项目下，不删除或丢失数据。

## D-020：行动项状态与项目连续回顾

- 日期：2026-09-15
- 状态：宁已确认
- 决策：行动项新增“待确认、进行中、已完成、已取消”四种人工状态；新行动项默认“待确认”。
- 连续口径：“未完成”只包含“待确认”和“进行中”，“已完成”和“已取消”不进入未完成清单。
- 信息边界：直接以单层项目作为连续会议范围，首版聚合最近 3 场已完成会议，不新增可见的会议系列或二级目录。
- 数据影响：新增结构化行动项状态表和更新接口；旧报告中的行动项在迁移时补为“待确认”，报告 JSON 保持兼容。
