# 声纹跨会议验收脚本

目的：验证“第一场人工确认一次，第二场自动识别”，同时观察新人和低置信度的安全回退。两场录音使用同一部手机、相近距离和普通会议环境，不要刻意模仿对方声音。

## 录音一：首次建立身份（3 人，约 3 分钟）

角色：宁总、小李、小王。每人一次尽量说 15-30 秒，不要抢话。

1. 宁总：“今天我们只确认两件事：第一，本周是否开放第一批用户；第二，谁负责收集反馈。先说我的结论，我建议周四开放二十个名额，但前提是支付失败提示必须今天修好。”
2. 小李：“我同意周四开放。现在支付本身没有失败，但网络超时时用户看不到原因。我今天下午补错误文案和重试按钮，明天上午给大家验收。”
3. 小王：“我负责用户反馈。我会建一张表，记录使用场景、问题、严重程度和是否影响付费。每天下午六点汇总，第二天早会说。”
4. 宁总：“那就定了：周四开放二十个名额；小李明天上午交支付错误提示；小王从开放当天开始每日汇总反馈。还有一个没定，名额用完后是否自动关闭申请，下次会再确认。”

第一场验收：报告中应出现说话人 1/2/3。分别填写姓名；若是别人的声音，勾选“已取得该参会者同意”后点击“确认并记住此声音”。

## 录音二：跨会议自动识别（3 人，约 2 分钟）

角色：宁总、小李、新参会者小周。宁总与小李必须由第一场的同一个人录制。

1. 小李：“支付错误提示已经修好，我测了断网和服务器超时两种情况，用户现在可以重试。”
2. 小周：“我是第一次参加。我建议每个申请用户都标记来源，否则二十个名额用完后，我们不知道哪个渠道有效。”
3. 宁总：“这个建议重要，但不阻塞周四开放。我做个决定：保持周四上线，小周今天增加渠道字段，名额用完后先关闭申请，不自动扩容。”

第二场验收：宁总和小李应直接显示真实姓名与“已识别”；新人小周应显示“待确认”。如任一旧成员匹配错误，立即记录置信度和录音条件，不把该阈值直接用于公网。
