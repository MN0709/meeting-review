最后核查：2026-09-13。

落地任务：[GitHub #2：历史会议搜索与周期会议回顾](https://github.com/MN0709/meeting-review/issues/2)

## 结论

Read AI、Granola 和 Fellow 是闭源商业产品。我们可以复现公开可见的产品模式和交互逻辑，但不能复制其源码、品牌或专有素材。

开源项目也不能看到代码就直接粘贴。只有确认许可证、依赖成本、安全边界和架构适配后才能采用；实际复制代码时必须记录来源、版本、许可证和修改范围。

## 已采用的产品模式

### Read AI：历史搜索与周期会议回顾

- 历史搜索范围必须明确为当前团队、当前项目或指定会议系列。
- 周期会议开始前，展示上次会议的关键决策、未完成行动项和遗留问题。
- 回顾不是重新生成一段泛泛摘要，而是结构化引用上次会议的数据。
- 跨会议回答必须返回来源会议和时间戳。

### Granola：项目资料库

- 团队 → 项目 → 会议。
- 项目是跨会议记忆和问答的边界。
- 会议可以先进入“未分类”，AI 只能提出归档建议。

### Fellow：报告

- 总览、关键要点、决策、行动项、遗留问题分开呈现。
- 决策和责任必须附证据，不埋在长段落里。

## 10 天内的技术选择

```text
用户查询
  -> team_id / project_id / series_id 权限与范围过滤
  -> SQLite 结构化字段筛选（决策、行动项、会议日期）
  -> SQLite FTS5 检索相关转写片段
  -> 只把候选片段交给 LLM 归并
  -> 返回会议来源、原话、时间戳
```

先使用 SQLite FTS5 的理由：项目已经依赖 SQLite，无额外服务和原生扩展；对于早期产品项目组的会议量，标题、标签、结构化行动项和全文关键词足以验证需求。只有真实问题证明同义词搜索不足时，才引入 embedding/sqlite-vec。

## 开源代码进入项目的门槛

1. 许可证允许当前发布方式。
2. 官方仓库仍在维护，来源和固定版本可追溯。
3. 复制比基于现有 FastAPI/SQLite 自己实现更省成本。
4. 不引入超出 4 GB 服务器承受范围的常驻服务。
5. 新依赖有测试、Docker 构建验证和安全检查。
6. 在 README 的第三方声明中记录归属。

会脉没有复制闭源竞品源码。WeSpeaker 以带版本锁定的依赖方式使用，其 Apache-2.0 许可证与引用信息在 README 中保留。
